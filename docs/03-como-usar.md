# 03 · Como usar

## Jeito 1 · Comando
```
/julgar Um app de delivery de marmitas fitness para academias de São Paulo
```

## Jeito 2 · Conversa natural
- "Claude, avalie meu projeto: ..."
- "Vale a pena continuar com essa ideia?"
- "Tem mercado para isso?"
- "Chame o tribunal para julgar meu bot."

## Jeito 3 · Com arquivos
Anexe um README, um PDF de apresentação ou o link do repositório. O Claude lê e monta o resumo.

## Como descrever bem o projeto
Quanto melhor a descrição, melhor o veredito. Tente responder:
1. **O que é?** (uma frase)
2. **Para quem?** (público-alvo)
3. **Que problema resolve?**
4. **Em que estágio está?** (ideia, protótipo, no ar)
5. **Como pretende ganhar dinheiro ou gerar impacto?**
6. **Com que recursos?** (tempo, equipe, orçamento, tecnologia)

### Modelo para copiar
```
/julgar
Projeto: [nome]
O que é: [1 frase]
Público: [quem vai usar]
Problema: [o que resolve]
Estágio: [ideia / protótipo / no ar]
Monetização: [como gera valor]
Recursos: [tempo, equipe, orçamento, stack]
```

## O que você recebe
1. Veredito do Juiz em destaque
2. Resumo de cada parecer
3. Tabela de notas e média
4. Análise de mercado
5. Projetos alternativos (se aplicável)
6. Próximos passos
7. Aviso de apoio à decisão

## Dicas
- Rode de novo depois de ajustar o projeto e compare a média.
- Se o Mal-humorado "exagerar", é esperado: o Juiz filtra o que não tem base.
- Peça "aprofunde o mercado" ou "compare com o concorrente X" para continuar a conversa.
- Não coloque segredos na descrição (veja o guia 06).
